# How I Choose Things

When I evaluate a machine, product, technology, or system, I tend to
reduce it to three layers:

1.  **Core**
2.  **Peripherals**
3.  **Consumables**

I generally prioritize them in exactly that order.

The core determines whether the thing fundamentally does its job.
Peripherals make it more capable or convenient. Consumables are things
that are expected to wear out and be replaced.

This sounds obvious, but it changes how I spend money.

## The motorcycle example

Take a motorcycle.

### 1. Core

The core is the part that makes it a motorcycle:

-   Engine
-   Fuel system --- carburetor or injector

If the core is unreliable, everything else is irrelevant.

### 2. Peripherals

Then there are the supporting systems:

-   Electrical system
-   Fuel pump
-   Radiator, if liquid-cooled
-   Drivetrain --- CVT, chain, etc.

These matter, but they should not dominate the decision if the
underlying machine is fundamentally sound.

### 3. Consumables

Finally:

-   Tires
-   Brake pads
-   Battery
-   Other wear items

I expect these to fail eventually. That is what they are for.

## Why I like Cubs

This is one reason I like Cub motorcycles so much.

A Cub is mechanically simple and extremely difficult to kill under
normal abuse.

There is **no clutch cable to worry about**. It is commonly
**air-cooled**, so there is no radiator and cooling-system headache. It
does not have a scooter-style **CVT** with its own collection of belts,
rollers, and related wear points.

And when I need more storage?

I add a box.

The problem is solved by adding a peripheral. I don't need to replace
the entire motorcycle because the motorcycle doesn't have enough
storage.

That distinction is important.

**Solve the problem at the layer where the problem exists.**

## The same idea applies to laptops

I think about laptops in much the same way.

### Core

-   CPU
-   iGPU / graphics capability

The processor and integrated graphics determine a large part of the
machine's fundamental capability.

### Peripherals

Things such as:

-   RAM
-   SSD
-   Display
-   Wi-Fi
-   Keyboard and trackpad
-   Ports
-   Cooling
-   Speakers
-   Webcam

These make the machine useful and comfortable.

### Consumables / replaceable parts

Depending on the design:

-   Battery
-   Storage
-   Fans
-   Other parts that predictably wear or age

This is also why I generally prefer **AMD integrated graphics over a
discrete NVIDIA GPU** for the kinds of computers I use.

A discrete GPU can be excellent. But it is another major component,
another power domain, another thermal source, another driver stack, and
another potential point of failure.

If I don't need it, why add it?

## Complexity has a price

More components can mean more capability. But they can also mean:

-   More failure modes
-   More maintenance
-   More heat
-   More power consumption
-   More software dependencies
-   More things to understand

This isn't an argument for making everything primitive.

It is an argument for **earning complexity**.

If a component solves a real problem, add it. If it exists mostly
because the specification sheet looks impressive, I am probably not
interested.

My ideal machine is not the machine with the most features.

It is the machine with **the fewest things that can go wrong while still
doing everything I actually need**.

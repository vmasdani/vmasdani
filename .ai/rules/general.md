# General

## Deploy artifact must keep blog/*.md and dual public dirs
Deployed on cPanel shared hosting: docroot is public_html/, but Laravel's public_path() resolves to base_path('public') because public_html/index.php bootstraps from dirname(__DIR__). So build/ must be uploaded to BOTH public/ (manifest lookup) and public_html/ (asset URLs). blog/*.md are runtime content read via base_path('blog') in app/Support/Blog.php — never exclude them from the artifact; exclude only root-level docs (AGENTS.md, CLAUDE.md, spec.md) using anchored '/NAME.md' patterns.

## public_html is the deploy docroot, regenerated by build.sh
Shared hosting serves the site from public_html and the docroot cannot be changed to point at Laravel's public/, so build.sh regenerates public_html as a mirror of public/ and packages the repo into ../vmasdani.zip. Deployment is only by uploading that zip, never from git, so public_html is gitignored and does not need committing; do not re-add it. Never exclude public_html from the zip or point Laravel's local docroot at it; the local docroot stays public/. Background-remover model assets are vendored by scripts/vendor-background-removal.sh into public/background-removal (and mirrored into public_html) and are gitignored — they must be fetched at build time, not committed.

## JS tooling is Bun, not npm/node
Use `bun install`, `bun run <script>` and `bunx`; never npm/npx. bun.lock is the only lockfile, so do not commit a package-lock.json. bunfig.toml sets `[run] bun = true`, which makes Vite, Vitest, ESLint and Prettier run on the Bun runtime even though their bins have node shebangs. Vite stays the bundler because laravel-vite-plugin writes the manifest that `@vite` reads.

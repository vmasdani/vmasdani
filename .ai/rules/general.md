# General

## Deploy artifact must keep blog/*.md and dual public dirs
Deployed on cPanel shared hosting: docroot is public_html/, but Laravel's public_path() resolves to base_path('public') because public_html/index.php bootstraps from dirname(__DIR__). So build/ must be uploaded to BOTH public/ (manifest lookup) and public_html/ (asset URLs). blog/*.md are runtime content read via base_path('blog') in app/Support/Blog.php — never exclude them from the artifact; exclude only root-level docs (AGENTS.md, CLAUDE.md, spec.md) using anchored '/NAME.md' patterns.

## public_html is the deploy docroot, regenerated by build.sh
Shared hosting serves the site from public_html and the docroot cannot be changed to point at Laravel's public/, so build.sh regenerates public_html as a mirror of public/ and packages the repo into ../vmasdani.zip. public_html is committed as the deploy artifact — source changes that affect public assets appear there as deleted/re-added build hashes. Never delete public_html or point Laravel's local docroot at it; the local docroot stays public/. Background-remover model assets are vendored by scripts/vendor-background-removal.sh into public/background-removal (and mirrored into public_html) and are gitignored — they must be fetched at build time, not committed.
